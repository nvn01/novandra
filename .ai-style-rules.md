## Golden Files

- `pages/index.js` — page composition, data passed through static props, and local `styled-jsx` for page-specific layout.

- `components/page/index.js` — shared page shell and metadata composition.

- `components/entry/text.js` — compact list-entry presentation.
- `lib/github.js` — async integration, normalization, timeout, and graceful fallback conventions.

## Naming & State-Control Rules

- Use single quotes and omit semicolons.
- Prefer `const` arrow functions and default exports for React components.
- Keep file order as imports, constants/helpers, component, data loader, export.
- Use the existing `@components`, `@data`, `@lib`, and `@styles` aliases.
- Reuse `Page`, `Link`, `Entry`, and `TextEntry` before introducing new presentation primitives.
- Keep page-specific visual rules in the existing CSS module or a local `styled-jsx` block.
- Keep content in `data/` when it is repeated, curated, or shared across pages.
- Use `getStaticProps` for build-time content and explicit `revalidate` only for remotely refreshed data.
- For external data, normalize it before rendering and keep a local fallback.
- Use stable content identifiers for React keys; do not use array indices for persistent collections.

## DONTs

- Do not replace Paco's page shell, typography system, spacing scale, content width, entry components, command menu, or theme behavior.
- Do not introduce card-heavy landing-page patterns, gradients, oversized hero sections, or a second design system.
- Do not add a dependency for content-only work.
- Do not let remote GitHub ordering decide the curated featured-project order.
- Do not present inherited Paco content as Novandra's authorship; mark provenance explicitly.
- Do not expose private career-document material or unverified claims.
- Do not remove or rewrite unrelated user changes in the dirty worktree.
